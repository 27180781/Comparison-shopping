# 02 — Data Sources

> **זה המסמך החשוב ביותר ברפו.** הוא מכיל ידע דומיין שאי אפשר להסיק מהקוד.
> קרא אותו במלואו לפני כתיבת קוד ingestion.

---

## 1. הרקע החוקי

חוק קידום התחרות בענף המזון, התשע"ד-2014 ותקנות שקיפות מחירים.
כל "קמעונאי גדול" (מחזור > 250 מיליון ₪) חייב לפרסם באתר אינטרנט:

1. קובץ חנויות הרשת
2. לכל חנות בנפרד — המחיר הכולל העדכני של כל מצרך
3. לכל חנות בנפרד — מכלול המבצעים

עדכון מחיר בפרסום עד שעה ממועד העדכון בקופות.
עמוד ריכוז הקישורים: `gov.il` → `cpfta_prices_regulations`.

**החוק מחייב פרסום — הוא לא מחייב פורמט אחיד.** מכאן כל הכאב שלהלן.

## 4. משפחות פורטלים

12 רשתות ≈ 4 דפוסי גישה. הספרייה מטפלת בכולם, אבל חשוב להבין למה:

### Cerberus — `url.retail.publishedprices.co.il`
פורטל משותף לרשתות רבות. **דורש התחברות** — שם משתמש לכל רשת.

### שופרסל — פורטל עצמאי
`prices.shufersal.co.il`. ללא התחברות. פורמט משלו.

### Bina Projects — `{chain}.binaprojects.com`
דף `Main.aspx` בכותרת "הורדות - חוק המזון", עם פילטרים:
`מחסנים | מחירים | מבצעים | מחירים מלא | מבצעים מלא`.
**ללא התחברות.** הטבלה ריקה בטעינה ומתמלאת ב־AJAX — רשימת הקבצים
מגיעה כ־JSON מ־endpoint נפרד. אם תצטרך אדפטר משלך: DevTools → Network → XHR.
**אותו דפוס בכל תת־דומיין** — אדפטר אחד מכסה כמה רשתות.

### API ייעודי
קבוצת יינות ביתן, ויקטורי (מקור חדש). לכל אחת API משלה.

## 5. 🔥 כאוס הפורמטים — המלכודות

| מלכודת | פירוט | טיפול |
|---|---|---|
| **קידוד** | חלק מהרשתות ב־UTF-16, לא UTF-8 | זהה BOM. אל תניח. |
| **דחיסה** | רוב gzip, חלק ZIP | sniff לפי magic bytes |
| **גודל** | 5–15MB לקובץ, מאות קבצים בריצה | `lxml.iterparse` בלבד |
| **סכמות** | שמות שדות שונים בין רשתות | מיפוי per-chain בקונפיג |
| **תאריכים** | פורמטים שונים | נרמל ל־ISO 8601 + `Asia/Jerusalem` |
| **מחירים** | לפעמים string עם רווחים / ריק | parse עם fallback ל־`NULL`, **לא 0** |
| **geo-blocking** | חלק מהאתרים חוסמים גישה מחו"ל | הרץ מ־IP ישראלי |

## 6. שדות מפתח

### פריט
- `ItemCode` — המזהה. **`ItemType` קובע מה הוא:**
  - `ItemType = 1` → ברקוד גלובלי (EAN-13/8). ניתן להתאמה חוצת־רשתות. ✅
  - `ItemType = 0` → קוד פנימי. שקיל / מותג פרטי. לא ניתן להתאמה ישירה. ⚠️
- `ItemName` — שם בעברית, פורמט חופשי לגמרי
- `ManufacturerName`, `ManufactureCountry`
- `UnitQty`, `Quantity`, `UnitOfMeasure`, `bIsWeighted`
- `ItemPrice`, `UnitOfMeasurePrice`
- `PriceUpdateDate`

### מבצע
שדות מובנים נפוצים: `PromotionId`, `PromotionDescription` (טקסט חופשי!),
`PromotionStartDate/Hour`, `PromotionEndDate/Hour`, `DiscountType`,
`RewardType`, `MinQty`, `DiscountRate`, `DiscountedPrice`, `ClubId`,
`AllowMultipleDiscounts`.

⚠️ **חלק מלוגיקת המבצע קיימת רק בטקסט החופשי של `PromotionDescription`.**
שם השדות המדויק משתנה בין רשתות — **מפה אמפירית ב־Phase 0**, אל תסמוך על
הרשימה הזו כמוחלטת.

## 7. שלוש קטגוריות מוצרים — הבנה קריטית

| קטגוריה | ברקוד? | התאמה חוצת־רשתות? | v1? |
|---|---|---|---|
| **מותג לאומי** (תנובה, אסם, שטראוס) | ✅ EAN-13 גלובלי | ✅ טריוויאלית | ✅ |
| **מותג פרטי** | ✅ בד"כ `729…` תקין | ❌ **אין מקבילה זהה** | ⏳ v2 |
| **שקיל / פתוח** (ירקות, בשר, דלפק) | ❌ קוד פנימי | ⚠️ ברמת קטגוריה בלבד | ⏳ v2 |

**התובנה שקל לפספס:** הבעיה במותג פרטי היא **לא** שחסר ברקוד — יש לו ברקוד
GS1 תקין לגמרי. הבעיה היא שהמוצר קיים רק ברשת אחת. אין "אותו קוטג' שופרסל
ירוק" ברמי לוי. שום שיפור באלגוריתם הברקוד לא יפתור את זה — צריך מושג אחר:
**מחלקות שקילות** (v2).

## 9. קיצור דרך ל־MVP

קיים dataset ציבורי ב־Kaggle עם נתונים מנורמלים, מתעדכן יומית
(מתוחזק ע"י פרויקט OpenIsraeliSupermarkets).

שווה לבנות עליו את לוגיקת הקטלוג והסל **לפני** שמקימים pipeline משלך —
מקצר את Phase 1 בשבועות. ה־pipeline העצמאי נדרש לפני production בגלל
טריות הנתונים ושליטה בזמינות.
